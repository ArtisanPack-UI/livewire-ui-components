# ArtisanPack UI Livewire UI Components

## [Unreleased]

## [3.0.0] - 2026-11-14

### Added
- `php artisan artisanpack:upgrade-ui`: upgrades an app's Blade files from the 2.x API to 3.0 (#67 in design-system, D-056). It renames components, attributes and slots, turns flags into values, merges per-part class attributes into `:classes`, moves a button's `label` into its slot, wraps tooltip attributes in `<x-artisanpack-tooltip>` and reads Button `variant` values (a color becomes `color`). `--dry-run` previews the changes as a diff. Attributes it can't decide and raw DaisyUI classes are reported with file, line and column and left alone, as are tags other packages register under the prefix (`x-artisanpack-ec-*`). The rules are `resources/design-system/upgrade-rules.php`, generated by the design system and copied by `scripts/build-assets.mjs`.
- `<x-artisanpack-dialog>` (design-system Dialog, #49 in design-system): a modal window on the behavior engine's dialog machine. `wire:model` binds the open state through `$wire.entangle()`; `role="alertdialog"` for confirmations; `size`, `surface`, `color`, `icon`, `title`, `description`, `footer`, `trigger`, `modal`, `portal`, `hideClose`, `closeLabel` and `classes`. Every part keeps a stable, server-rendered id.
- `<x-artisanpack-dropdown-menu>` with `dropdown-menu-item`, `dropdown-menu-group` and `dropdown-menu-separator` (design-system DropdownMenu, #50): action, checkbox and radio items, groups with labels, shortcuts and danger items, scoped `dropdown-menu`. `items` renders the same children from data. Items carry `wire:key` and the machine's ids.
- `<x-artisanpack-toaster>` (design-system Toast, #51): the region that shows toasts from data. It listens for the `toast` browser event, so `$this->dispatch( 'toast', title: … )` shows one, and shows toasts flashed to the session once (not again when `wire:navigate` restores a page from history). It is `@persist`ed, so toasts survive `wire:navigate`, as the 2.x toaster did.
- `Support\Toasts`: `make()`, `flash()`, `push()` and `pull()` for toast options, so a toast survives a redirect (`Toasts::flash( title: … )` from a controller).
- `Traits\Toast::flashToast()`.
- `View\Concerns\HasStablePartIds` and `Support\RenderedIds`: overlay ids that are unique on the page (they include the Livewire component's id, and repeats in a render get `-2`, `-3`) and never depend on text or open state, so a re-render keeps them; plus the `wire:model` open-state binding.
- `php artisan artisanpack:generate-preset`: generates a brand preset from the design-system tokens (`data-preset`), with luminance-matched color ramps and a WCAG 2.2 AA check in every theme before it writes anything. Outputs CSS, PHP or JSON. (#27 in design-system)
- `Theming\PresetGenerator`, `GeneratedPreset`, `DesignTokens`, `ContrastChecker` and `ColorMath`: a PHP port of the design system's `apui-generate-preset`, tested against its golden fixtures for identical output.
- `Theming\TokenThemes` (theme, density and preset attributes, contrast checks, `prefers-contrast` and `prefers-color-scheme` CSS) and `Theming\GlassSurface` (`data-surface="glass"`).
- `resources/design-system/tokens.php`: the design-system token map.
- Form wave on the design system (#53 in design-system): `<x-artisanpack-validation-summary>`, `<x-artisanpack-color-picker>` (the spec's popover with area, hue and opacity sliders, format select, eyedropper and swatches, on the color-picker machine), `<x-artisanpack-code-editor>` and `<x-artisanpack-rich-text-editor>` (TinyMCE under the design-system toolbar when the page loads it, the built-in editor otherwise). Every built-in string is a `*-label` prop defaulting through `__()`.
- `<x-artisanpack-combobox>` (#54 in design-system, D-020): one component for Choices, ChoicesOffline and Tags. Filtering is local, or `remote` with a `search-model` set after `debounce`; `multiple` renders chips, `allow-create` offers "Create …", `max` caps the count, and `name` submits the value through hidden inputs. `wire:model` binds the value through `$wire.entangle()`.
- `<x-artisanpack-date-picker>` (#55 in design-system, D-021): the date picker on the behavior engine's machine, with `mode="range"` and a `time` mode, ISO 8601 values bound through `$wire.entangle()`, typing in the field, and month and weekday names in the app locale.
- `<x-artisanpack-navbar>` and `navbar-item`, and `<x-artisanpack-breadcrumbs-item>` (#56 in design-system).
- Select's `options` take `{ label, options }` groups, rendered as `<optgroup>` (D-025).
- The prebuilt assets and the Lucide icon set are rebuilt from the design system, adding the Tabs, DatePicker, ColorPicker, Spotlight, Combobox and form-editor Alpine components and the icons they draw.
- Layout, Feedback and Data Display waves, Tooltip and Table on the design system (#58 to #62 in design-system, D-029 to D-044):
  - New: `<x-artisanpack-tooltip>` (on the behavior engine; it puts the trigger attributes on your own control), `accordion-item`, `app-shell`, `page-header`, `divider`, `grid`, `stack`, `list`, `avatar-group`, `user-menu` (Avatar + DropdownMenu, with a `logout-action` form), `skeleton`, `empty-state`, `error-state` and `timeline`.
  - Engine widgets for Accordion, Collapse, Drawer, Popover, Tooltip, ImageSlider (carousel) and the ImageGallery lightbox, with stable server-rendered part ids.
  - Sparkline and Diff render on the server with no JavaScript (`Support\SparklineGeometry`, `Support\DiffBuilder`), so `wire:poll` redraws them.
  - Every built-in string is a `*-label` prop defaulting through `__()`.
- The prebuilt assets and the Lucide icon set are rebuilt from the design system for these components.
- Chart, Calendar and the Utility wave on the design system (#63 to #65 in design-system, D-045 to D-055):
  - New: `<x-artisanpack-clipboard>` (button, icon and copy-field variants, announced in a live region), the stateless `<x-artisanpack-calendar>` that `<livewire:artisanpack-calendar>` renders, and `@apuiThemeScript`, which applies the stored theme before first paint.
  - Chart and Calendar render on the server (`Support\ChartGeometry`, `Support\CalendarModel`) from the same math as React and Vue; Chart is an SVG with keyboard-reachable marks, tooltips and a `tabular` data table.
  - Markdown renders with `league/commonmark` (now a dependency), with raw HTML escaped and unsafe links dropped; `mode="write"` and `mode="split"` add the editor tabs.
  - Swap, Kbd, Code, Icon, Carousel and ThemeToggle are rebuilt on the design-system markup; ThemePreview is a Blade card picker.
  - Every built-in string defaults through `__()` and can be overridden: as props on Code, Clipboard, Carousel, Markdown, ThemeToggle and ThemePreview (`*-label`, plus `label`, and Clipboard's and Code's `copied-message` and `error-message`), and as a `labels` array on Calendar and Kbd (Kbd's names the symbol keys for screen readers).
  - Chart accepts ApexCharts-style points (`[ 'x' => …, 'y' => … ]`, `[ x, y ]`), whose `x` fills the labels when none are given, and a `null` `series`; its numbers round exactly as the React and Vue charts do. `<livewire:artisanpack-calendar>` accepts an explicit `null` for `view` and `events`.
  - Markdown with `mode="write"` or `"split"` works in a plain form: `name` reaches the editor, and its tabs share one value, so the latest source is posted once.
  - A ThemeToggle bound with `wire:model` applies the server's value on load, when it differs from the stored choice, and whenever the server changes it. ThemeToggle starts on `@apuiThemeScript`'s `default` when nothing is stored (the head script records `data-theme-choice`); bound and `:persist="false"` toggles ignore other tabs' stored choices.
  - ThemePreview's `aria-label` and `aria-labelledby` name the radio group, and a null `wire:model` property checks no card.
  - Calendar: the week start follows the locale without `ext-intl` (built-in CLDR week data; names stay English), invalid event times are skipped, events ending at 00:00 name the next day, previous and next advance once per click before a re-render, "+N more" moves focus to the day it opens, and the details child remounts when an event changes and ignores `loadEventModal` from other calendars (it now carries `calendarId`).
  - Chart's y axis handles any finite range, a viewBox of 48×36 or less falls back to the default, and empty `options.xaxis.categories` fall through to `options.labels`.
  - Markdown: native control attributes (`required`, `disabled`, `readonly`, `placeholder`, `maxlength`, `rows`, …) go to the editor, a plain form posts the source from any tab and previews the draft in the browser, a debounced `wire:model` is flushed before the preview commits, nesting and delimiter runs are capped (100 and 500), and raw `<img>` `data:` URLs are limited to PNG, GIF, JPEG and WebP.
  - Code copies the exact source. Clipboard captures the value once and shows a manual-copy field after a failed copy. Carousel remounts when its slide count or options change, keys slides by `id` and puts the autoplay control first in the Tab order. Icon passes `classes.svg` to blade-icons fallbacks and respects a caller's `aria-label`. Swap's `data-state` follows a form reset.

### Changed
- Built on the published design system: `@artisanpack-ui/css` and `@artisanpack-ui/behavior` 1.0.0 and `@artisanpack-ui/tokens` 2.0.0. The installer offers the bundler path (npm + Vite), which installs the CSS and behavior packages at `^1`; the prebuilt files stay the default.
- **Breaking:** `<x-artisanpack-toast>` is now the design-system Toast rendered on its own: a static toast (`title`, `description`, `color`, `variant`, `surface`, `icon`, `actions`, `hideClose`, `closeLabel`, `classes`) whose close button dispatches `open-change`. The toaster that 2.x rendered with `<x-artisanpack-toast />` is `<x-artisanpack-toaster />`; its `position`, `color`, `colorAdjustment`, `duration` and glass props are gone.
- **Breaking — positional calls change meaning:** 2.x `toast()` took `( $type, $title, $description )`; 3.0 takes `( $title, $description, $color )`. Calls whose first argument is a color name and second is set raise an `E_USER_DEPRECATED` notice to help you find them, and then `$this->toast( 'success', 'Saved' )` shows a toast titled "success" with "Saved" as its text, without an error, while `$this->toast( 'success', 'Saved', 'Details' )` throws an `InvalidArgumentException` because "Details" is now the color. Rewrite them as `$this->toast( 'Saved', 'Details', color: 'success' )` or `$this->success( 'Saved', 'Details' )`. In `success()`, `warning()`, `error()` and `info()` the third argument was `$position` and is now `$duration` (an int), so a 2.x call passing a position throws a TypeError. `ToastException`'s third argument was `$position` and is now `$icon`; an invalid icon there falls back to no icon instead of failing.
- A bare `<x-artisanpack-toast />` (the 2.x toaster) renders nothing and raises an `E_USER_DEPRECATED` notice pointing to `<x-artisanpack-toaster />`.
- **Breaking:** `Traits\Toast::toast()` takes `( $title, $description, $color, $variant, $surface, $icon, $duration, $hideClose, $redirectTo )`, and `success()`, `warning()`, `error()` and `info()` take `( $title, $description, $duration, $redirectTo )`. `position`, `css` and Heroicons icon names are gone; icons are registry names. With `redirectTo` the toast is flashed and shows on the next page.
- **Breaking:** `ToastException` answers with the new toast options (`{ toast: { title, description, color, … }, prevent_default }`); its constructors take `( $title, $description, $icon, $duration )`.
- **Breaking:** the `artisanpack-toast` browser event and `window.toast()` are gone. Dispatch `toast`, or call `ApuiBehavior.toast()`.
- The `ap.livewireUiComponents.toastDispatched` action receives the toast's color (was its type), title and options.
- The installer's layout stub uses `<x-artisanpack-toaster />`, and the Welcome stubs use the new trait signature.
- The prebuilt assets and the Lucide icon set are rebuilt from the design system (adds `circle-check`, `triangle-alert`, `pencil`, `log-out`, `settings`).
- Require Laravel 12 or 13 (`illuminate/support: ^12.0|^13.0`) and PHP 8.2. Laravel 11 is end of life, and Composer now refuses its releases over unpatched security advisories.
- Allow `laravel/boost` 2.x, Pest 4 and PHPUnit 12 in development, which Laravel 13 needs, and drop `pestphp/pest-plugin-watch`, which has no Pest 4 release.
- **Breaking:** rebuilt in place on the design system, keeping their tags: `textarea`, `password`, `pin`, `range`, `toggle`, `fieldset`, `form`, `radio-group`, `checkbox-group`, `rating`, `file`, `signature`, `breadcrumbs`, `link`, `pagination`, `steps`/`step`, `tabs`/`tab`, `menu`/`menu-item`/`menu-sub`/`menu-title`/`menu-separator` and `spotlight`. Their DaisyUI props (`*-class`, `inline`, `omit-error`, `first-error-only`, `prefix`/`suffix`, color and glass props) are gone; each docs page has an "Upgrading from 2.x" section. The ones most likely to need changes:
  - Pin: `size` (the cell count) is `length`, and `size` is now the cell size; `numeric` is `type`; `hide`/`hide-type` is `mask`; `completed`/`incomplete` are one `complete` event.
  - Password: `strength-meter`, `requirements` and `reveal-label` replace the icon and visibility props.
  - Fieldset: `subtitle` is `description`. Toggle: `hint` is `description`. Form: `no-separator` is gone, and `divided` adds the edge.
  - Pagination: `rows` takes the paginator; `summary` and `summary-label` replace `page-info-template`; the size and layout variants are gone. Table keeps its "Rows per page" select.
  - Steps: `value` counts from 1; the 2.x step panels are gone.
  - Breadcrumbs: `items` or `breadcrumbs-item` children; links placed in the slot still render as levels.
  - Link, Breadcrumbs, NavbarItem, Spotlight and Menu items add `wire:navigate` to internal links by default, as in 2.x; `:navigate="false"` turns it off. Off-site, `#`, `mailto:` and new-tab links load normally. `no-wire-navigate` still works on Link, Breadcrumbs and Menu items, deprecated.
  - Spotlight: `searchText`, `noResultsText`, the `append` slot and the dotted shortcut spelling (`meta.g`) still work as deprecated aliases of `placeholder`, `emptyText`, `footer` and `mod+g`. Endpoint results take a registry `icon` name, not HTML. Recent choices are opt-in (`recent`).
  - Tabs and Menu keep the 2.x attributes downstream code uses (`tab name`, `tabs selected`, `menu-item title`/`link`/`active`/`no-wire-navigate`, `menu activate-by-route`).
- **Breaking:** the `colorpicker` class is renamed `ColorPicker` (PHP class names are case-insensitive, so they can't coexist), and the `colorpicker` tag renders the new component.
- **Breaking:** Accordion, Collapse, Drawer, Popover, Heading, Text, ListItem, Avatar, Badge, Alert, Loading, Progress, ProgressRadial, StreamableContent, Stat, KpiCard, Sparkline, TimelineItem, Diff, ImageGallery, ImageSlider, ImageLibrary and Table are rebuilt on the design-system markup. DaisyUI classes, glass props and `ColorGenerator` colors are gone; each component's docs page has an "Upgrading from 2.x" section. Most 2.x attributes still work, deprecated.
- **Breaking:** Drawer opens at the end edge by default (2.x opened at the start). Popover opens on click as a non-modal dialog.
- **Breaking:** the `tooltip`, `tooltip-left`, `tooltip-right`, `tooltip-bottom` and `tooltip-position` props are gone. Wrap the control in `<x-artisanpack-tooltip content="…">`.
- **Breaking:** on Table, `class` and other attributes land on the root `<div>`, not the `<table>`. `compact` sets `density="compact"`, and `with-pagination` is `paginated`. An empty table always shows the empty state, and `selectable` and `expandable` can be combined.
- **Breaking:** Heading's `level` defaults to 2 (was 1).
- **Breaking:** Clipboard dispatches `copied` instead of `copy` (which collides with the browser's native copy event); rename `x-on:copy` to `x-on:copied`.
- **Breaking:** Chart's default `type` is now `bar` (2.x: `line`), and a bar chart draws only the first series; add `type="line"` to keep 2.x charts with several series.
- `artisanpack:generate-theme --preview` no longer prints a preview URL or route instructions, because the `/artisanpack/theme-preview` page was removed; it prints a notice pointing to #142. The interactive mode no longer asks for a preview URL.
- **Breaking:** Chart no longer uses ApexCharts. `options` is ignored except for its categories, labels and title; `pie` becomes `donut`; `width` and `height` are viewBox units; the theme, animation and glass props and the `chart-update*` events are gone.
- **Breaking:** Markdown renders by default. The EasyMDE editor and its image uploads are gone; use `mode="write"` or `mode="split"` for an editor bound with `wire:model`.
- **Breaking:** Code is read-only (no Ace editor); use `<x-artisanpack-code-editor>` to edit code. Icon's `label` is now the accessible name, not visible text, and the default size is 16px.
- **Breaking:** ThemeToggle writes `data-theme` on `<html>` and stores the choice under `apui-theme` (the `mary-theme` and `mary-class` keys are no longer read). The `theme-changed` events become `value-change`; the default is the segmented control (`variant="icon"` for the 2.x button).
- **Breaking:** Calendar's week start follows the locale unless `week-starts-on` or `sunday-start` is set, and it's no longer lazy by default. Carousel's `interval` defaults to 5000ms and it wraps only with `loop`.
- ImageLibrary keeps the `WithMediaSync` contract (`wire:model`, `wire:library`, `:preview`); cropping runs in a design-system Dialog when Cropper.js is on the page.

### Fixed
- **Security:** the `artisanpack.upload` route, which the RichTextEditor (TinyMCE) and Markdown components post images to, stored any file on any disk and folder the request named. It now takes images only (JPG, PNG, GIF, WebP and AVIF by default, never SVG), up to `max_size` kilobytes, on a disk in the new `uploads.disks` config (default `public`), in a folder made of letters, numbers, dashes, underscores and slashes, so it can't leave the disk. Anything else gets a 422. Configure it under `uploads` in `config/artisanpack/livewire-ui-components.php`.
- `Stat::numericValue()` read "$12,345" as 12.345: a single comma followed by three digits is now a thousands separator; one or two digits is still a decimal.
- `Table` currency formats such as `['currency', '2.,', '$']` threw a TypeError under strict types.
- `ImageLibrary::modelName()`, `ImageLibrary::libraryName()`, `ImageLibrary::validationMessage()` and `Rating::size()` returned objects where they declare strings, which threw a TypeError.
- `SelectGroup` crashed rendering grouped options, which are a collection.
- `Tab` without a `label` threw a TypeError while rendering.
- `Header` rendered an empty `id=""` when it has no anchor.
- A custom `prefix` broke every component that renders other components (Alert, Dialog, Table and 30 more). Components now also register under the internal `artisanpack-` names, which the package's views use. An empty prefix registers bare names (`<x-button>`), and a trailing hyphen is ignored, so `'artisanpack-'` no longer gives `artisanpack--button`.
- The installer no longer force-publishes `config/livewire-ui-components.php` over an existing file when it finds Jetstream, Breeze or Flux. It warns when the prefix is empty instead.
- The installer's starter layout and demo pages are rewritten for 3.0: AppShell, Menu, UserMenu, PageHeader, Table and Drawer, with `@apuiThemeScript` and the toaster, no DaisyUI classes, and the demo pages' mismatched closing tags fixed.
- `artisanpack:generate-ide-helper` listed nothing but Spotlight. It now lists every registered Blade and Livewire component under the configured prefix.
- The `ap.livewireUiComponents.componentClasses` filter now runs for Skeleton and the child components (accordion, menu, navbar, timeline, dropdown-menu items, tabs and steps), as it already did for every other component's root.
- `@island`, `@endisland` and `@placeholder` replaced Livewire 4's own directives. They're now registered only on Livewire 3.
- StreamableContent left out `wire:stream` on Livewire 3, which has supported it since 3.0.

### Deprecated
- `<x-artisanpack-modal>` and `<x-artisanpack-dropdown>`. Use `<x-artisanpack-dialog>` and `<x-artisanpack-dropdown-menu>`. They're removed in a later major release.
- `artisanpack:generate-theme`, `Styling\ColorGenerator`, `Styling\GlassPresets` and `Styling\HighContrastTheme`. Use `artisanpack:generate-preset`, `Theming\PresetGenerator`, `Theming\GlassSurface` and `Theming\TokenThemes`. They're removed once the components that use them move to the design system.
- `<x-artisanpack-choices>`, `<x-artisanpack-choices-offline>` and `<x-artisanpack-tags>` (use `combobox`), `<x-artisanpack-datepicker>` and `<x-artisanpack-datetime>` (use `date-picker`, with `time` for the latter), `<x-artisanpack-select-group>` (use `select` with option groups), `<x-artisanpack-radio>` and `<x-artisanpack-group>` (use `radio-group`; `group` is `variant="segmented"`), `<x-artisanpack-errors>` (use `validation-summary`), `<x-artisanpack-editor>` (use `rich-text-editor`), `<x-artisanpack-colorpicker>` (use `color-picker`) and `<x-artisanpack-nav>` (use `navbar`). They're removed in a later major release.
- `<x-artisanpack-main>`, `<x-artisanpack-header>`, `<x-artisanpack-separator>`, `<x-artisanpack-widget-grid>`, `<x-artisanpack-profile>` and `<x-artisanpack-subheading>`. Use `app-shell`, `page-header`, `divider`, `grid`, `user-menu` and `text size="lead"`.

### Removed
- The flatpickr date picker theme CSS and JS. DatePicker runs on the behavior engine and is styled by the design-system tokens.
- Table's virtual scroll, export toolbar and its events (`TableExporter` stays), `striped`, `no-hover`, `container-class`, `header-glass*` and the `row-selection` events.
- Divider's (2.x `separator`) loading bar (`progress`, `target`): use Progress.
- The PhotoSwipe hooks in ImageGallery and ImageSlider; ImageGallery has a built-in lightbox.
- `resources/js/sparkline.js`, the diff2html Diff renderer and the `jfcherng/php-diff` dependency.
- `Support\ChartThemes`, the EasyMDE Markdown editor and its upload query, and the `<livewire:theme-preview>` theme builder with its `/artisanpack/theme-preview` route.
- The maryUI `livewire-ui-components:bootcamp` command and its stubs, and the installer's maryUI sponsor line.
- The `artisanpack-glass-tokens` and `artisanpack-design-tokens` publish tags, and the unread `icons.list_item` and `icons.loading` config keys. The `theme_output_path`, `glass` and `design_tokens` keys stay, deprecated, for `artisanpack:generate-theme`.
- The DaisyUI and glass-token Boost guidelines. The core guideline is rewritten for 3.0.

## [2.1.0] - 2026-07-21

### Added
- Cross-cutting UI extension hooks powered by `artisanpack-ui/hooks`. Nine seams for applications and third-party packages to extend rendered classes, attributes, icons, toasts, table columns, theme configuration, modal lifecycle, and spotlight commands without editing individual components. See the "Extension Hooks" section of the README for the full table. (#108)
  - `ap.livewireUiComponents.componentClasses` filter — opt-in per component via `$this->getClasses($classes)`
  - `ap.livewireUiComponents.componentAttributes` filter — fires on every component render
  - `ap.livewireUiComponents.iconAlias` filter
  - `ap.livewireUiComponents.toastDispatched` action
  - `ap.livewireUiComponents.tableColumns` filter
  - `ap.livewireUiComponents.themeColors` filter
  - `ap.livewireUiComponents.modalWillOpen` / `modalWillClose` actions (via `Support\ModalBridge`)
  - `ap.livewireUiComponents.spotlightCommands` filter
- New `ArtisanPack\LivewireUiComponents\View\Components\BaseComponent` abstract class that all Blade components now extend. Provides the shared render-pipeline seams for classes and attributes.
- New `ArtisanPack\LivewireUiComponents\Support\ModalBridge` helper for firing modal lifecycle hooks server-side.

### Changed
- Require `artisanpack-ui/hooks: ^1.2`.

### CI
- Drop Laravel 10 from the CI test matrix. The ecosystem dependencies (`artisanpack-ui/hooks`, `icons`, `accessibility`, `core`) all now require `illuminate/support: ^11+`, so composer cannot resolve a Laravel 10 test run regardless of this package's own constraint.
- Run Feature tests unconditionally (`if: always()`) so new Feature-suite coverage exercises even when pre-existing Unit-suite failures make the earlier step exit non-zero.

## [2.0.0] - 2026-01-23

### Added

#### Dashboard Components
- **KpiCard**: New component for displaying KPIs with sparklines, trend indicators, and glass effects
  - Supports sparkline visualization (area, line, bar charts)
  - Automatic trend indicator coloring (green for positive, red for negative)
  - Glass effect support with customizable tints
  - Footer slot for additional content
- **WidgetGrid**: Responsive grid helper for dashboard layouts
  - Configurable column count (1-6 columns)
  - Automatic responsive breakpoints
  - Configurable gap spacing
- **Sparkline**: Inline sparkline chart component
  - Supports area, line, and bar chart types
  - Customizable colors

#### Table Data Export
- **TableExporter**: New utility class for exporting table data
  - CSV export (client-side)
  - XLSX export via PhpSpreadsheet (server-side)
  - PDF export via DomPDF (server-side)
  - Automatic header normalization for Table component format
  - Hidden column filtering
- **WithTableExport**: New trait for Livewire components
  - Handles `table-export-request` events
  - Provides `exportTableToCsv()` and `exportTableToXlsx()` methods
  - Abstract `getTableExportData()` method for customization
- **Table component**: New export props
  - `exportable` - Enable export functionality
  - `export-formats` - Configure available formats (csv, xlsx, pdf)
  - `export-filename` - Custom filename for exports
